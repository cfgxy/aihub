## 2. 架构

```mermaid
flowchart LR
  subgraph 公开前台（无账号）
    A[首页：资源类型分栏+分类导航] --> B[列表页：分类/筛选]
    B --> C[详情页：字段集+获取动作]
    A --> S[搜索]
  end
  subgraph 数据层
    DB[(SQLite)]
  end
  subgraph 管理侧（仅本机/口令保护）
    M[管理页 /admin：条目 CRUD+上下架]
  end
  C -- 跳官方/复制命令/下载指引 --> EXT[官方站/来源仓库]
  M --> DB
  A & B & C & S --> DB
```

- **技术栈**：Next.js（App Router）单体应用 + SQLite；具体版本与驱动由开发按当前稳定版选定并在项目 `CLAUDE.md` 记录。
- **搜索**：SQLite 查询起步（数百至数千条规模足够）；出现性能证据后再评估 FTS5，不预做。
- **分类侧数据驱动**：资源类型与类型下分类均为数据库数据，前端不写死分类数量——这是 Q5 结构的直接推论，也是「分类要产品规划」可演进的前提。

## 3. 数据模型草案（开发可按实现微调，字段语义不变）

- `resource_types`：id, key（app / skill / mcp）, name, sort
- `categories`：id, type_id, name, description, sort —— 类型下分类（Q5）；一条目归属规则（单/多分类）待分类体系 v2 定，建模时预留
- `resources`：id, name, slug, type_id, category_id(s), summary, tags, official_url, source_url, install_guide, icon, status（draft/published）, created_at, updated_at
- 种子 7 项随首个 migration/seed 入库，`status=published`。

## 4. 分发语义（Q3-A 目录模式）

| 资源类型 | 「获取」动作 | 站内托管 |
|---|---|---|
| 应用 | 新开官方下载页 | 否 |
| SKILL | 跳来源仓库/页面下载技能包 + 展示标准安装说明（复制） | 否 |
| MCP | 复制 JSON 配置或安装命令 | 否 |

## 5. 安全与合规

- 管理页：单管理员口令，仅存本地 `.env`（不入 Git、不入日志）；MVP 默认仅本机访问；不做多用户账号体系。
- 外链：`rel="noopener nofollow"` + 站内免责声明（D1/D3 口径）；第三方名称/图标仅识别性引用并标注来源。
- 不托管安装包（D2=否）、无 UGC（D5 规避）、无凭据类外部协议。

## 6. 演进路径

1. **MVP（本单）**：Web 响应式 + 三资源类型 + 类型下分类 + 搜索/详情/获取动作 + 管理 CRUD + 种子 7 项。
2. **自动收录管道**：白小巡每日 02:00 定时任务——搜索 AI 领域新资源，精选 10 条开 Issue 报 Owner 审批；Issue 中指定谢小婷做写手、黄小云做插图素材；审批通过经管理页入库。**cron 由 Leader 在 MVP 验收（入库通道可用）后创建**，本期不建。
3. **二期评估**：移动 App / PC 客户端；UGC 投稿；公网上线与备案（Owner 明示延后）。

## 7. 风险与对策

| 风险 | 对策 |

## 8. ADR 摘要

- ADR-001 轻后端（Next.js+SQLite+管理页）：Owner 选定 T2-B；驱动因素是 Q6 审批入库需要可运营的写入口，纯静态站无便捷入库通道。回退：内容可导出为静态数据源降级。
- ADR-002 目录模式分发（Q3-A）：不托管安装包，规避分发授权与包安全风险。回退：Owner 改选托管时重议 D2。
- ADR-003 分类结构（Q5 Owner 改判）：资源类型→类型下分类两级；分类数据由产品规划维护，架构数据驱动。回退：分类仅增删数据行，无 schema 级回退需求。
